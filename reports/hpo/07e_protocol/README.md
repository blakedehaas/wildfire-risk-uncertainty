# Phase 7E: frozen five-success geographic HPO protocol

## Approval and scope

The approved primary evaluation uses **five successful random-startup suggestions** for each remaining outer study 1, 2, 4, and 5. Every configuration receives all five inner geographic folds and 100 epochs. The unrestricted original search space, equal-fold/equal-task validation log-skill objective, GradNorm settings, spatial splits, preprocessing, and training implementation remain unchanged. The `TPESampler(seed=42, n_startup_trials=10)` is retained, but the study stops at five completions, so the effective search is random startup, not adaptive TPE. No pilot-informed hyperparameter restrictions apply to the primary evaluation.

[The committed protocol manifest](protocol_manifest.json) records study identities and paths, seeds, sampler and pruner, objective and selection rules, success and attempt limits, original data/split/cache fingerprints, fold preprocessing hashes, implementation-file hashes, and the outer-3 pilot database hash. It was generated before any new training. At launch the runner recomputes and compares these fingerprints, then persists the manifest digest in Optuna provenance. Outer TEST targets are excluded from this process.

## Budget, failures, resume, and selection

Each new study persists a **success budget of five** and an **attempt safety cap of 25**. `FAIL` attempts remain in Optuna and the audit; the next suggestion replaces them until five trials are `COMPLETE`. A `RUNNING` trial resumes its saved configuration and local checkpoints before any new suggestion. The controller stops with a visible error if 25 attempts are exhausted without five successes. The prior lifetime-attempt-budget mechanism remains readable for the completed outer-3 pilot, but the Phase 7E runner refuses to reopen it. The detached launcher, direct CLI, resume route, and historical study-extension mutation routes all reject outer-3 modifications under this manifest.

The best of the **first five successful completions** is selected by the frozen objective, with the earliest Optuna trial number breaking an exact tie. The pilot's [predefined comparison](pilot_selection.csv), generated by [a read-only script](../../../scripts/report_07e_pilot_selection.py), selects trial **0** (0.10449623942546031) under that first-five rule. The original 20-success pilot still selects trial **19** (0.10821307369969084). Both are inner-validation selections. Trial 19 is retained as the original pilot optimum and is reported separately; neither result has used outer TEST. The five-success comparison is fixed now and must not be altered after held-out evaluation.

The same seed 42 and same unrestricted sampler are used for each independent Optuna study. Therefore the first random suggestions can coincide across outer studies; failures can change which trial numbers make up the first five successes. Saved sampler RNG state is restored on resume. No change to seed or search space was made to increase apparent candidate diversity.

## Isolation and readiness

Each outer study has its own SQLite database (`artifacts/hpo/outer_{j}_gradnorm_v3.sqlite3`), Optuna name (`wildfire_outer_{j}_gradnorm_hpo_v3`), record/checkpoint root, fold-specific preprocessing, and W&B run group/name carrying that study identity. W&B runs for this protocol are tagged `random-search`. The `outer_study` passed to the existing cache/fold provider selects that study's original frozen geographic partition. The completed outer-3 database and record root are separate and protected.

The read-only [readiness checker](../../../scripts/check_07e_readiness.py) validates the manifest, clean committed source, absence of an outer-1 GradNorm database/records or active controller, pilot count and fingerprint, and available CUDA memory. W&B online authentication was checked separately at preparation time and is checked again by the launcher before work. It does not start a trial or inspect outer TEST targets. Exact command, **only after the requested GPU-execution review**:

```bash
uv run python scripts/benchmark_07a_detached.py launch --kind gradnorm_hpo --outer-study 1 --trial-limit 5 --gradnorm-objective-reviewed
```

The launch command creates a detached supervised run; the returned experiment ID is used with `status`, `stop`, and `resume`. Outer studies 2, 4, and 5 are not launched in this phase.

## Reporting and remaining risks

This is a **revised-protocol geographic evaluation**, distinct from the originally planned prospectively fixed 20-success-per-study nested-CV experiment. Each new study's outer TEST remains isolated from its own HPO. The protocol-level budget revision followed the outer-3 pilot, whose TRAIN population may overlap other outer TEST populations, so the pooled five-study estimate must be described as revised-protocol geographic sensitivity, not an unqualified prospectively fixed nested-CV estimate. Outer-3's untouched held-out result and its original 20-success selection should remain separate from the first-five comparable analysis.

Five random suggestions can miss a good region; Phase 7D gives no assurance of practical equivalence to the 20-trial winner. The safety cap can stop a study without five successes, requiring scientific review. Optuna's saved RNG state and exact-source resume gate protect normal interruption/resume paths; an interruption inside the tiny interval between partial parameter persistence and RNG-state persistence remains an infrastructure risk and must be audited before resuming. Runtime and W&B availability can change. No outer TEST outcome may be used to revise the budget, candidate rule, or stopping condition.

# Checkpoint 5B: outer spatial cross-validation

**HITL status: approved and frozen before model development.** The row-level `05b` artifact and primary report tables use the deterministic uniform fitting sample accepted at the engineering review. The earlier stripe-sample geometry survives only in the superseded comparison and ignored archive.

Spatial evaluation is used because nearby training observations can share response structure with a held-out location; unrestricted proximity would not measure transfer to locations separated from training by the BP dependence range. This scheme estimates geographic-transferability performance for locations whose usable training data are separated by more than the BP-derived spatial dependence radius. A future out-of-fold (OOF) prediction for a canonical cell uses a model trained without that cell and without any canonical observation at Euclidean cell-center distance at or below the exclusion radius. It does not estimate random-CV performance, ordinary interpolation performance, design-unbiased CONUS map accuracy, or performance of a later all-data production model. This checkpoint creates geometry only; it fits no predictive model.

## Scalable, deterministic implementation

The frozen canonical support has 110,817,231 rows in 3,060 Parquet tiles on a 17,372 × 11,283 EPSG:5070 grid with 270 m cell spacing. The constructor reports and per-partition SHA-256 hashes are checked before use. Files are read in sorted tile-name order and rows retain increasing `cell_id` order. `PYTHONHASHSEED=42` is mandatory.

Ordinary full-batch k-means across all canonical cells is impractical. The corrected fitting sample contains exactly 1,097,262 canonical rows drawn uniformly without replacement. In sorted canonical tile and row order, `random.Random(42).sample(range(110817231), 1097262)` selects distinct integer row positions. Each canonical row has one unique position and therefore equal inclusion probability. The sorted positions are matched while streaming one tile at a time; only `cell_id`, `x_5070`, and `y_5070` are read. This uses O(sample size) memory, not an all-row in-memory coordinate array. The sampled cell IDs are persisted and hashed. The selected coordinates are permuted with NumPy seed 42 before scikit-learn MiniBatchKMeans fits five clusters with batch size 16,384, ten initializations, and no reassignment. Python's built-in hash is not used.

This exact uniform draw and MiniBatchKMeans fitting are engineering scale adaptations to Euclidean coordinate k-means, not new scientific partition rules. Every canonical row is assigned to its nearest fitted centroid using both coordinates only. Final fold IDs are ordered by ascending centroid x then y. Mini-batch fitting still approximates the ordinary full-batch k-means optimum; membership may differ. Folds are not target-balanced because their membership must remain a coordinate-only spatial partition; target, predictor, WUI, and row-count differences are diagnostic outcomes, never optimization inputs. No targets, predictors, or state boundaries enter sampling, fitting, assignment, or relabeling. The fitting-sample audit counts all 101 native column residues and verifies that no residue is empty. The original implementation's `cell_id % 101 == 0` fitting sample aliased with the 17,372-column raster and produced periodic north–south stripes; it is retained only as pre-HITL implementation provenance and is not the accepted fitting method.

Each fold's TEST cells are rasterized on the native grid. SciPy's exact Euclidean distance transform gives cell-center distance to the nearest TEST cell; non-test canonical cells at `distance <= r` are DEAD_ZONE, and those at `distance > r` are TRAIN. A second transform gives every TEST cell's nearest usable TRAIN distance. The transform is evaluated over the full grid, so raster holes are transparent geometry and never become model observations. Native 270 m spacing is supplied in metres; classification uses float64 distance and the unrounded radius. The stored OOF distance is float64.

The row-level artifact retains only `cell_id`, one-based `outer_fold`, `oof_nearest_training_distance_m`, and five training-eligibility booleans. For each canonical cell, `oof_nearest_training_distance_m` is the exact Euclidean distance to the nearest usable TRAIN cell in the fold where that cell is TEST; every value is strictly greater than the radius. Tiles align with canonical Parquet tiles. Reports contain full-support counts and means. BP and FLEP8 audit quantile columns are explicitly labeled `sample_estimated` and retain the earlier deterministic `cell_id % 101 == 0` diagnostic subset; this subset never enters fold fitting. Nearest-training quantiles use all test cells and are exact. Conditional FLEP8 is `FLP5 + FLP6` only where the canonical `flp_target_valid` mask is true. Unconditional FLEP8 is zero for BP-zero cells and `BP × (FLP5 + FLP6)` for BP-positive valid cells; it is undefined for BP-positive invalid FLPs. WUI summaries measure canonical coverage and failure flags, without using them to choose folds.

## Validation and scope

The independent validator reconstructs support and assignments from persisted tiles, compares every ID to the canonical tile, reassigns every coordinate to the persisted nearest centroid, and recomputes exact grid distances separately for all five folds. It checks status exhaustiveness, the strict radius boundary, complete training eligibility, exact OOF nearest-training distances, and one test fold per canonical row. The constructor checks source hashes before and after writing. Any failure stops the run.

This is the frozen outer assessment design, approved before any model development. Every canonical cell becomes TEST in exactly one of the five folds. Spatial inner resampling for hyperparameter tuning is deferred to a later literature-grounded checkpoint. The fixed five-fold geometry and 211.151 km BP radius may yield different test/training sizes and target distributions; those are reported, never optimized away. Euclidean EPSG:5070 distance is a projected cell-center distance, not terrain-path or geodesic distance.

Rebuild with `PYTHONHASHSEED=42 uv run wildfire-spatial-folds`. Validate with `PYTHONHASHSEED=42 uv run wildfire-validate-folds`. A bounded rerun with `PYTHONHASHSEED=42 uv run wildfire-reproduce-folds` checks the persisted uniform sample IDs, byte-identical centroids, the fold-label stream digest for all rows, and byte-identical regeneration of every row-level Parquet tile. `PYTHONHASHSEED=42 uv run wildfire-reproduce-fold-reports` regenerates deterministic compact tables, figures, and README. The independent validator separately repeats all five exact dead-zone and OOF distance calculations; the reproducibility commands do not repeat those transforms. The manifest records software versions, sample provenance, centroids, radius, source provenance, runtime, and partition digests.

The smallest OOF nearest-training distance is reported at full precision in the distance summary. Classification and OOF distance validation use float64 native-grid distances and the exact radius; rounding a displayed kilometre value must not be used to assess the strict inequality.

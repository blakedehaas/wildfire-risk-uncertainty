# Phase 7A: fixed GradNorm training method

## Authority and scope

[Chen et al. (2018), Algorithm 1](https://proceedings.mlr.press/v80/chen18a/chen18a.pdf) is the methodological authority. The [LibMTL GradNorm code at commit `4336804847eaa5e0b924b743d76beec7ac3fdc97`](https://github.com/median-research-group/LibMTL/blob/4336804847eaa5e0b924b743d76beec7ac3fdc97/LibMTL/weighting/GradNorm.py) was inspected as an implementation reference on 2026-10-22. LibMTL documents asymmetry `alpha=1.5`; we fix `gradnorm_alpha=1.5` without tuning it. GradNorm is adopted from prior literature. We make no methodological novelty or predictive superiority claim.

The [former static-alpha Pareto protocol](checkpoint_07a_loss_balancing.md) was superseded before any sweep ran. Its 25-fold gradient probe and three-epoch throughput audit are retained as development evidence. No new dataset, predictor, preprocessing, spatial split, seed, model architecture, or outer TEST access is introduced. BP is one Bernoulli task; the six conditional FLP classes form **one** categorical task. Training-only mean imputation, coverage indicators, and strict FLP-validity masks remain frozen. Later uncertainty evaluation must stratify performance by missing-feature pattern and coverage.

## Equations and implementation

For tasks `i ∈ {BP, FLP}`, the predictive losses are separate-support means: Bernoulli cross entropy for BP and six-class categorical cross entropy only on FLP-valid rows. The network objective at step `t` is `L(t)=Σ_i w_i(t)L_i(t)`. For an FLP-empty minibatch, the FLP term is absent and its weight receives no update; BP uses its current weight. The production global-support correction for FLP minibatch gradients is retained. Neither FLP target imputation nor an extra GradNorm task per class is permitted.

The shared parameter subset `W` is the **weight matrix of the last shared backbone Linear layer**, `RiskMLP.backbone[-2].weight`, for every supported depth. GradNorm uses `G_i=||∇_W[w_i L_i]||₂`, `Ḡ=mean_i G_i`, `ℓ_i=L_i(t)/L_i(0)`, and relative inverse rate `r_i=ℓ_i/mean_j ℓ_j`. It minimizes `L_grad=Σ_i |G_i−stop_gradient(Ḡ r_i^1.5)|`. The paper specifies separate gradients for the task weights and network, followed by task-weight renormalization to `Σ_i w_i=2`. Our code obtains each unweighted shared-layer gradient once, detaches its norm, and multiplies by the weight parameter. Thus only the two weights receive the `L_grad` gradient. The ordinary weighted predictive loss uses detached weights, so it updates only network parameters. Both gradients are calculated using the pre-update weights; the model AdamW and weight Adam steps then run, followed by renormalization.

Weights start at `(1,1)` and are stored as FP32 parameters. A separate Adam optimizer uses learning rate **0.025**, the weight-update rate reported for the paper's NYUv2 experiments; its weight decay is zero. The network retains its existing AdamW optimizer, learning rate and decay supplied by the fixed configuration or original HPO search space. There is no network scheduler in the current production pipeline. A post-step positive projection at `1e−8` before sum-to-two normalization enforces the requested positive-weight constraint; this numerical safeguard is an implementation detail beyond the paper's explicit renormalization equation. All predictive forward passes retain CUDA BF16 autocast; cross entropies and gradient norms are evaluated in FP32 and internal KL rates in FP64. There is no loss-scale search, static-alpha sweep, or new model architecture.

The paper uses direct initial task losses from training start. LibMTL's inspected implementation instead adapts only when `epoch >= 1`, normalizes raw parameter logits through `T·softmax`, and uses a stored first-epoch loss buffer. We follow the paper's **first eligible minibatch, pre-update** reference and per-step updates, with a documented soft-target adaptation below. If that first minibatch lacks FLP support, BP receives an ordinary weighted update and both references wait for the first batch containing valid FLP. A nonpositive initial rate fails explicitly because its ratio is undefined; no artificial reference or smoothing constant is invented.

## Soft probabilistic targets and rate measurement

For a fixed probabilistic target `p`, `CE(p,q)=H(p)+KL(p||q)`, and the target entropy has zero predictive gradient. Hence BP and FLP network updates continue to use the proper cross entropies. For soft Dillon/FSim targets, however, a large irreducible entropy floor can compress `CE(t)/CE(0)` even when predictive divergence changes substantially. We therefore use each task's **unweighted KL** only to form the GradNorm relative training-rate ratio. KL is computed from logits and targets in FP64 as cross entropy minus target entropy on the same minibatch support, with `xlogy` at zero target probabilities. The first positive KL from a batch with both tasks is stored as that task's reference. This is an **application-specific adaptation**, not an equation or empirical claim from Chen et al. or LibMTL. Changing minibatch target composition can still make rates noisy; a short smoke cannot establish long-run behavior. If both KL rates later vanish, the relative rate is undefined and the implementation must keep weights unchanged for that step; if only one vanishes, its relative rate is zero. Larger negative or nonfinite KL values fail. Predictive CE, validation CE/KL, and GradNorm diagnostics are logged separately. The dynamic weighted training loss is never used to rank models.

## Nested HPO and review gate

The new HPO study name and SQLite file are separate from historical 6E/6F equal-weight studies. The five outer TRAIN populations, five inner folds, dead zones, 33 inputs, TPE architecture and network-optimizer search space, seed 42, and two-worker fold execution remain unchanged. GradNorm constants are **not** trial parameters. All GradNorm state, its Adam optimizer, first-step references, model and AdamW states, epoch/global step, Python/NumPy/PyTorch CPU and CUDA RNG states, and data/preprocessing provenance are checkpointed at epoch boundaries. Fold records include predictive losses, final weights, mean shared-layer norms, mean relative rates, update/FLP-empty counts, and mean `L_grad`; validation retains separate BP/FLP CE and KL. The detached launcher completed the one-epoch, five-inner-fold GradNorm calibration `07a-20261022T032107Z-870036d5` with two processes and four CPU threads each. Its HPO mode supervises one outer study, whose existing provider owns two fold workers; a kernel parent-death signal prevents orphaned workers if the HPO process dies. HPO status, progress, logs, worker exits, resource samples, Optuna state, and fold checkpoints persist. No GradNorm HPO run has launched.

The 06F epoch-4 fidelity diagnostic rejected early pruning. The separate GradNorm study therefore uses `NopPruner` and retains the 100-epoch cap; its milestone reports are diagnostic only. Existing HPO ranking is the five-fold mean of `0.5·BP validation CE + 0.5·FLP validation CE`. The arithmetic gives equal coefficients, yet the observed losses differ markedly in numerical scale (outer-study-3 fold 1 at the calibration's first epoch: BP `0.0453`, FLP `1.6530`), so this scalar may effectively favor FLP changes. GradNorm does not resolve that **model-selection** question. Replacing the HPO objective would be a separate methodological decision; no arbitrary alternative is introduced here. The real HPO command requires an explicit objective-review flag and must remain unlaunched until that decision. Outer TEST stays off-limits.

## Validation, budget, and limits

Deterministic tests check the published equations, detached targets, weight/network gradient isolation, initial weights, positivity and sum-two normalization, masked soft targets, KL-versus-CE predictive gradients, FLP-empty batches, CUDA BF16, and complete checkpoint/resume equivalence. Three short outer-study-3 inner-TRAIN CUDA instrumentation passes ([first](../../reports/training/07a/gradnorm_smoke.json), [memory repeat](../../reports/training/07a/gradnorm_smoke_memory.json), [final source](../../reports/training/07a/gradnorm_smoke_final.json)) each used 16 real 65,536-row batches of the representative 3×128 model; all losses and weights stayed finite. Their median GradNorm/network steps were **7.69, 7.22, and 7.71 ms** versus **6.04 ms** in the historical warm 64-step benchmark (**19–28% higher for that stage**). The final pass peaked at **218.35 MB CUDA allocation** versus the historical 218.21 MB, and **2.02 GB process RSS** versus the historical 3.28 GB; its pre-batch process RSS was 0.87 GB. RSS is dominated by differently warmed mmap pages and cannot isolate GradNorm's host-memory overhead; no positive process-RSS signal appears in this short comparison. These are nonpaired measurements with different cache states and timing boundaries, not an end-to-end speedup or 100-epoch estimate. The existing equal-weight full-validation calibration measured 2.29 hours per five-fold, 100-epoch evaluation, making **344 hours** a mechanical historical rate for 150 unpruned evaluations before GradNorm and architecture variation. A preliminary **400–600 hour** planning allowance includes those effects but has not been measured end to end.

The [completed calibration review](../../reports/training/07a/gradnorm_calibration_review.md) found final epoch-1 BP weights of `0.032–0.158` across five folds, mean BP relative KL rates of `0.089–0.104`, and mean weighted BP shared-layer norms of `0.0085–0.0117` against FLP `0.370–0.426`. A single inner-TRAIN continuation of fold 1 reached the positive floor on 10 steps across epochs 2–3 and ended at BP weight `0.00595`; median BP share of the weighted shared-layer norm was `0.28%` in epoch 3. The KL rate differs substantially from a CE-derived rate calculated offline on the same early trajectory, so the soft-target adaptation and first-minibatch reference require methodological review. The two-worker calibration had no swap or memory pressure. **Production HPO is on hold** pending review of the rate definition/reference and per-task validation behavior. The HPO validation scalar's task-scale issue remains separately open. No outer TEST region was inspected.

## Publication-ready Methods paragraph

The following draft describes the implemented candidate and must be revised if the held rate formulation changes during methodological review.

We trained a shared multilayer perceptron to predict burn probability and the conditional distribution over six flame-length classes. Burn probability used Bernoulli cross entropy; flame length used categorical cross entropy only where a conditional target was valid. To balance their contributions during training, we applied GradNorm (Chen et al., 2018) to gradients at the final shared layer, with the published asymmetry parameter fixed at 1.5. Task weights were initialized equally, updated separately from network parameters, constrained to be positive, and normalized to sum to two. Because the simulation-derived targets are probabilistic, relative task-training rates were calculated from excess log loss (KL divergence), while network parameters continued to minimize the proper cross-entropy losses. Model selection used only inner spatial validation folds within each outer training partition; outer test regions were excluded from selection.

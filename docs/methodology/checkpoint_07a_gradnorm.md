# Phase 7A: fixed GradNorm training method

## Authority and scope

[Chen et al. (2018), Algorithm 1](https://proceedings.mlr.press/v80/chen18a/chen18a.pdf) is the methodological authority. The [LibMTL GradNorm code at commit `4336804847eaa5e0b924b743d76beec7ac3fdc97`](https://github.com/median-research-group/LibMTL/blob/4336804847eaa5e0b924b743d76beec7ac3fdc97/LibMTL/weighting/GradNorm.py) was inspected as an implementation reference on 2026-10-22. LibMTL documents asymmetry `alpha=1.5`; we fix `gradnorm_alpha=1.5` without tuning it. GradNorm is adopted from prior literature. We make no methodological novelty or predictive superiority claim.

The [former static-alpha Pareto protocol](checkpoint_07a_loss_balancing.md) was superseded before any sweep ran. Its 25-fold gradient probe and three-epoch throughput audit are retained as development evidence. No new dataset, predictor, preprocessing, spatial split, seed, model architecture, or outer TEST access is introduced. BP is one Bernoulli task; the six conditional FLP classes form **one** categorical task. Training-only mean imputation, coverage indicators, and strict FLP-validity masks remain frozen. Later uncertainty evaluation must stratify performance by missing-feature pattern and coverage.

## Equations and implementation

For tasks `i ∈ {BP, FLP}`, the predictive losses are separate-support means: Bernoulli cross entropy for BP and six-class categorical cross entropy only on FLP-valid rows. The network objective at step `t` is `L(t)=Σ_i w_i(t)L_i(t)`. For an FLP-empty minibatch, the FLP term is absent and its weight receives no update; BP uses its current weight. The production global-support correction for FLP minibatch gradients is retained. Neither FLP target imputation nor an extra GradNorm task per class is permitted.

The shared parameter subset `W` is the **weight matrix of the last shared backbone Linear layer**, `RiskMLP.backbone[-2].weight`, for every supported depth. GradNorm uses `G_i=||∇_W[w_i L_i]||₂`, `Ḡ=mean_i G_i`, `ℓ_i=L_i(t)/L_i(0)`, and relative inverse rate `r_i=ℓ_i/mean_j ℓ_j`. It minimizes `L_grad=Σ_i |G_i−stop_gradient(Ḡ r_i^1.5)|`. The paper specifies separate gradients for the task weights and network, followed by task-weight renormalization to `Σ_i w_i=2`. Our code obtains each unweighted shared-layer gradient once, detaches its norm, and multiplies by the weight parameter. Thus only the two weights receive the `L_grad` gradient. The ordinary weighted predictive loss uses detached weights, so it updates only network parameters. Both gradients are calculated using the pre-update weights; the model AdamW and weight Adam steps then run, followed by renormalization.

Weights start at `(1,1)` and are stored as FP32 parameters. A separate Adam optimizer uses learning rate **0.025**, the weight-update rate reported for the paper's NYUv2 experiments; its weight decay is zero. The network retains its existing AdamW optimizer, learning rate and decay supplied by the fixed configuration or original HPO search space. There is no network scheduler in the current production pipeline. A post-step positive projection at `1e−8` before sum-to-two normalization enforces the requested positive-weight constraint; this numerical safeguard is an implementation detail beyond the paper's explicit renormalization equation. All predictive forward passes retain CUDA BF16 autocast; cross entropies and gradient norms are evaluated in FP32. There is no loss-scale search, static-alpha sweep, or new model architecture.

The paper uses direct initial task losses from training start. The pinned LibMTL implementation instead trains epoch 0 with equal weights, stores each task's average first-epoch training loss, and begins adaptation when `epoch >= 1`. We follow this **LibMTL schedule**: all first-epoch network steps use weights `(1,1)`; after exact traversal of the frozen task supports, the two separate-support mean training cross entropies become fixed initial references. Adaptive weight updates start with epoch 2. If an individual minibatch lacks FLP support, only BP updates the network and the GradNorm weight optimizer does not step. LibMTL uses `T·softmax(raw_weights)` while our direct positive weights retain the paper's explicit sum-to-`T` renormalization and existing separate Adam optimizer. Both methods keep weights positive and normalized, but their optimizer parameterizations differ.

## Soft probabilistic targets and rate measurement

For a fixed probabilistic target `p`, `CE(p,q)=H(p)+KL(p||q)`, and target entropy has zero predictive gradient. BP and FLP network updates use the existing masked cross entropies. **GradNorm's relative training rates also use those cross entropies**, each measured as an unweighted mean on that task's valid minibatch support and divided by its exact first-epoch separate-support mean. The production network loss retains its global FLP-support correction, which preserves the established epoch objective under streaming batches; that correction is not applied to the reported per-task CE rate. A nonpositive or nonfinite CE reference/rate fails explicitly. Excess log loss remains an independent validation metric and does not determine weight updates or HPO ranking. The dynamic weighted training loss is not used to rank models.

The prior version used first-minibatch KL references and KL-derived relative rates. Its [completed calibration review](../../reports/training/07a/gradnorm_calibration_review.md) found amplified BP/FLP rate imbalance and repeated BP weight-floor contacts. That version is retained only as immutable historical artifacts at source commit `2277daf31f638332d136ca5181ce213d39570cce`; current checkpoints reject its `initial_kl` state explicitly. The CE/first-epoch implementation has provenance version `checkpoint-07a-gradnorm-ce-epoch1-v2`, a separate Optuna study name and SQLite file, and fresh checkpoint metadata. No legacy KL-rate trajectory is silently resumed.

## Nested HPO and review gate

The new HPO study name and SQLite file are separate from historical 6E/6F equal-weight studies and the unlaunched KL-rate v1 study. The five outer TRAIN populations, five inner folds, dead zones, 33 inputs, TPE architecture and network-optimizer search space, seed 42, and two-worker fold execution remain unchanged. GradNorm constants are **not** trial parameters. All GradNorm state, its Adam optimizer, first-epoch CE references, model and AdamW states, epoch/global step, Python/NumPy/PyTorch CPU and CUDA RNG states, and data/preprocessing provenance are checkpointed at epoch boundaries. Fold records include predictive losses, final weights, mean shared-layer norms, mean relative rates, update/FLP-empty counts, and mean `L_grad`; validation retains separate BP/FLP CE and KL. The detached launcher completed the historical one-epoch, five-inner-fold KL-rate calibration `07a-20261022T032107Z-870036d5`. Its prepared HPO mode supervises one outer study, whose existing provider owns two fold workers; a kernel parent-death signal prevents orphaned workers if the HPO process dies. HPO status, progress, logs, worker exits, resource samples, Optuna state, and fold checkpoints persist. No GradNorm HPO run has launched.

The 06F epoch-4 fidelity diagnostic rejected early pruning. The separate GradNorm study therefore uses `NopPruner` and retains the 100-epoch cap; its milestone reports are diagnostic only. Existing HPO ranking is the five-fold mean of `0.5·BP validation CE + 0.5·FLP validation CE`. The arithmetic gives equal coefficients, yet the observed losses differ markedly in numerical scale (outer-study-3 fold 1 at the calibration's first epoch: BP `0.0453`, FLP `1.6530`), so this scalar may effectively favor FLP changes. GradNorm does not resolve that **model-selection** question. Replacing the HPO objective would be a separate methodological decision; no arbitrary alternative is introduced here. The real HPO command requires an explicit objective-review flag and must remain unlaunched until that decision. Outer TEST stays off-limits.

## Validation, budget, and limits

Deterministic tests check the published equations, detached targets, weight/network gradient isolation, initial weights, positivity and sum-two normalization, masked soft targets, KL-versus-CE predictive gradients, FLP-empty batches, CUDA BF16, and complete checkpoint/resume equivalence. Three short outer-study-3 inner-TRAIN CUDA instrumentation passes ([first](../../reports/training/07a/gradnorm_smoke.json), [memory repeat](../../reports/training/07a/gradnorm_smoke_memory.json), [final source](../../reports/training/07a/gradnorm_smoke_final.json)) each used 16 real 65,536-row batches of the representative 3×128 model; all losses and weights stayed finite. Their median GradNorm/network steps were **7.69, 7.22, and 7.71 ms** versus **6.04 ms** in the historical warm 64-step benchmark (**19–28% higher for that stage**). The final pass peaked at **218.35 MB CUDA allocation** versus the historical 218.21 MB, and **2.02 GB process RSS** versus the historical 3.28 GB; its pre-batch process RSS was 0.87 GB. RSS is dominated by differently warmed mmap pages and cannot isolate GradNorm's host-memory overhead; no positive process-RSS signal appears in this short comparison. These are nonpaired measurements with different cache states and timing boundaries, not an end-to-end speedup or 100-epoch estimate. The existing equal-weight full-validation calibration measured 2.29 hours per five-fold, 100-epoch evaluation, making **344 hours** a mechanical historical rate for 150 unpruned evaluations before GradNorm and architecture variation. A preliminary **400–600 hour** planning allowance includes those effects but has not been measured end to end.

The [historical KL-rate calibration review](../../reports/training/07a/gradnorm_calibration_review.md) found final epoch-1 BP weights of `0.032–0.158` across five folds and repeated BP floor contacts in a fold-1 continuation. It motivated the reference-aligned revision above. The [CE-rate three-epoch validation](../../reports/training/07a/gradnorm_ce_reference_review.md) then kept BP weight above 1.02, had no floor contacts, and measured median BP weighted shared-gradient share of 10.6–12.8% after warmup. FLP validation KL improved from `0.6754` to `0.6072`, while BP validation KL worsened from `0.00730` to `0.00901` by epoch 3. Elevated-BP validation predictions remained strongly below targets with weak within-stratum association. **Production HPO and full 100-epoch training remain on hold** pending review of BP transfer behavior. The HPO validation scalar's task-scale issue remains separately open. No outer TEST region was inspected.

## Publication-ready Methods paragraph

The following draft describes the CE-rate implementation; full-study results are pending.

We trained a shared multilayer perceptron to predict burn probability and the conditional distribution over six flame-length classes. Burn probability used Bernoulli cross entropy; flame length used categorical cross entropy only where a conditional target was valid. To balance their contributions during training, we applied GradNorm (Chen et al., 2018) to gradients at the final shared layer, with asymmetry fixed at 1.5. The first epoch used equal task weights and established separate-support mean cross-entropy references. Thereafter, task weights were updated from relative cross-entropy training rates, constrained to be positive, and normalized to sum to two. Excess log losses were reported independently as predictive validation metrics. Model selection used only inner spatial validation folds within each outer training partition; outer test regions were excluded from selection.
